---
title: Request Lifecycle
description: Learn how SKIM Framework handles incoming HTTP and CLI requests.
---

Every HTTP request in SKIM follows a single, linear, highly predictable path from entry to exit:

```php
App::instance()            // lightweight object creation only
  → $app->use(...)         // global middleware (e.g. Cors, ToolbarMiddleware)
  → require routes.php     // route definitions via $app->router
  → $app->run()
    → ensureBooted()       // lazy boot: router, pipeline, extensions
    → bootExtensions()     // extension routes (e.g. skim/auth)
    → Request::fromGlobals()
    → router->dispatch()
    → middleware pipeline (onion model)
    → controller handler
    → Response::send()
```

### Key Lifecycle Stages

1. **Bootstrap & Entry Point**: All HTTP traffic is routed to `public/index.php`, which calls `App::instance()` followed by `$app->run()`. `App::instance()` creates the singleton object without booting subsystems — boot is deferred until the first request.
2. **Lazy Boot**: Inside `run()`, `ensureBooted()` initialises the router, pipeline, and extensions only once. Env and config are loaded on-demand when first accessed.
3. **Request Initialization**: The `Request` class captures global state using `Request::fromGlobals()` — this happens only inside `App::run()`.
4. **Routing**: The router dispatches the request against the registered route definitions.
5. **Middleware Onion**: The request is passed through the registered middleware layers sequentially — global first, then group, then route-level.
6. **Controller Dispatch**: The matched controller or closure is executed with auto-injected parameters.
7. **Response Send**: The resulting `Response` object is sent back to the client via `Response::send()`.

### Error & Flow Control

SKIM does not use exception-based flow control for standard routing events.
* If a route is not found, the router returns `null` to indicate a **404 Not Found**.
* If the request method is not allowed, the router returns `false` to indicate a **405 Method Not Allowed**.

### Dependency Injection & Auto-Injection

Controller parameter resolution is flexible — parameters are auto-injected by name or by type-hint:
*   `Request` (the current request instance)
*   `Response` (the current response instance)
*   Route parameters (dynamic URL path tokens like `@id`)
*   Any class registered in the DI container

### CLI Request Lifecycle

CLI requests bypass the HTTP layer completely. Running `php skim <command>` boots the application container in CLI mode — `ArgvParser` splits arguments and flags (`--flag=value`, `--flag`), and `Cli\Kernel` resolves the target command via the command map — core commands plus anything registered under `commands` in `config/app.php`.
