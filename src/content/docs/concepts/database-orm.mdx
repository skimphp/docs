SKIM provides a database toolkit in two layers: a raw SQL template engine (`query_gen`) and an Active Record ORM. All parameters are bound — never interpolate user input into a query string.

### 1. Raw Queries — query_gen

`Db::` methods accept SQL templates with `%placeholder%` markers plus `:named` parameters:

```php
$users = Db::all("SELECT * FROM users WHERE active = :active", ['active' => 1]);
$user  = Db::row("SELECT * FROM users WHERE id = :id", ['id' => 3]);
$count = Db::val("SELECT COUNT(*) FROM users");
```

`Db::query()` returns rows for `SELECT`, `rowCount` for DML — or the interpolated SQL string with `debug: true` (query never executes).

### Conditional Clauses — `%where%`, `%set%`, `%values%`

Template placeholders expand from the params array:

```php
// %where% builds AND-conditions; removed entirely when empty or all-null
$users = Db::all(
    "SELECT * FROM users %where% ORDER BY created_at DESC %limit%",
    [
        'where'  => ['active = :active', 'city = :city'],
        ':active' => 1,
        ':city'   => $city,
        'limit'   => 50,
    ],
);

// %set% builds the SET list — null values are SKIPPED, not written
Db::query(
    "UPDATE users %set% WHERE id = :id",
    ['set' => ['name' => $name, 'email' => $email], 'id' => $id],
);
```

*   `%where%` absent + populated `where` array → `WHERE` injected automatically.
*   `%where%` present + empty/all-null conditions → clause removed silently.
*   `null` inside `%set%` → column skipped. To write a real `NULL`, use `Db::null()`.
*   `or`/`and` keys nest into `(a AND b) OR (c AND d)` groupings.

### 2. The `Db::null()` Sentinel

<NoteBox>
To explicitly persist SQL `NULL` in `%set%` or `->update()` payloads, use the sentinel — plain `null` means "skip this column":

```php
Db::query("UPDATE users %set% WHERE id = :id", [
    'set' => ['suspended_at' => Db::null()],
    'id'  => 1,
]);
```
</NoteBox>

### 3. Active Record ORM

Extend `Model` to work with tables as objects:

```php
namespace App\Models;

use Skim\Db\Model;

class User extends Model {
    protected static string $table = 'users';
}

// Fetch and update — dirty tracking updates only changed columns
$user = User::find(1);        // null when missing — never throws
$user = User::findOrFail(1);  // throws NotFoundException
$user->email = 'new@example.com';
$user->save();                // INSERT without PK, UPDATE with PK
```

Property hooks run on every assignment; `id`/`created_at`/`updated_at` use asymmetric visibility — writable only inside the model. `$guarded` columns are never mass-assigned.

### Merry ORM — Relations

`MerryModel` adds relations (defined in static arrays, no annotations) and eager loading via `with()` — it takes an already-fetched model collection:

```php
class User extends MerryModel {
    protected static string $table = 'users';
    // protected static array $relations = ['posts' => ...];
}

$users = User::all("SELECT * FROM users WHERE active = :a", [':a' => 1]);
$users = User::with($users, 'posts.comments'); // dot notation for depth
```

`attach()`/`detach()`/`sync()` are available on many-to-many relations.
