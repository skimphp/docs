`profiler` is a static event collector that records framework operations (DB queries, cache ops, view renders, log entries) during a request. All methods are no-ops when disabled, ensuring zero overhead in production. The toolbar reads collected events for display.

```txt
Symbol: Skim\Dev\Profiler
Source: src/Dev/Profiler.php
Lifecycle: created empty at boot, enabled by App::run() when APP_DEBUG=true, populated during request, read by toolbar, reset between requests
Fallback: all recording methods are no-ops when disabled
Test seam: enable()/disable() to toggle, reset() to clear between tests
```

<CodeExample label="Basic usage" source="llm-generated">
```php
Profiler::enable();
// ... request processing ...
$summary = Profiler::summary();  // ['db' => ['count' => 5, 'ms' => 12.3], ...]
$events  = Profiler::events();  // raw event array for toolbar
```
</CodeExample>

## Architecture

<LifecycleFlow>

```txt
enable()
-> db()/cache()/view()/log() during request
-> summary()/events() for toolbar
-> reset() between requests
```

</LifecycleFlow>

Static facade pattern — all state is process-local. Called by framework internals (db.php, cache.php, view.php, log.php) after every operation.

## Control

</ApiMethod>

<ApiMethod name="disable">

<ApiSignature>

```php

```

</ApiSignature>

</ApiMethod>

<ApiMethod name="reset">

<ApiSignature>

```php
public static function reset(): void
```

</ApiSignature>

Clears the event buffer without disabling the profiler. Call in tests between requests to isolate per-request data.

</ApiMethod>

<ApiMethod name="panel">

<ApiSignature>

```php
public static function panel(string $id, string $label, array $options): void
```

</ApiSignature>

Registers a custom toolbar panel for user-defined debug extensions. #AI:panel

Use in controllers, middleware, or extensions to add debug panels to
the toolbar. Panels appear as additional tabs after the built-in ones.
When $html is provided, it renders directly. When $template is set,
the toolbar renders it via dev_view with $data.

Example:
Profiler::panel('htmx', 'htmx Debug', [
'icon' =&gt; 'arrows exchange',
'data' =&gt; ['swaps' =&gt; 3, 'boosts' =&gt; 1],
]);
