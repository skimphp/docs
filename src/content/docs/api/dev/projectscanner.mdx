`ProjectScanner` is the top-level entry point for the docs extraction pipeline. It walks directories, finds .php files, and delegates extraction to `ClassExtractor`. Supports both config-driven and explicit path scanning.

```txt
Symbol: Skim\Dev\Docs\Extractor\ProjectScanner
Source: src/Dev/Docs/Extractor/ProjectScanner.php
Lifecycle: instantiated per-use by commands, extractor created once in constructor
Fallback: non-directory paths silently skipped
Test seam: instantiate directly
```

<CodeExample label="Basic usage" source="llm-generated">
```php
$scanner = new ProjectScanner();
$classes = $scanner->scan();               // uses config scan_paths
$classes = $scanner->scanPaths(['/app']); // explicit paths
```
</CodeExample>

## Architecture

<LifecycleFlow>

```txt
scan()
-> read config scan_paths
-> iterate paths
-> phpFiles() recursive
-> extractor.extract()
-> collect non-null results
```

</LifecycleFlow>

No framework dependencies beyond the config() helper.

## Scanning

<ApiMethod name="scan">

<ApiSignature>

```php
public function scan(): array
```

</ApiSignature>

Reads scanPaths from config/docs.php, recursively finds all .php files in each path, runs ClassExtractor on each, and returns a flat ExtractedClass[] with nulls discarded.

</ApiMethod>

<ApiMethod name="scanPaths">

<ApiSignature>

```php
public function scanPaths(array $paths): array
```

</ApiSignature>

Scans the given explicit paths instead of config scan_paths. Same null-discard behaviour as scan(). Used by commands that override paths via --source flag.

<ApiParam name="$paths" type="string[]" required>

Directories to scan recursively for .php files.

</ApiParam>

</ApiMethod>
