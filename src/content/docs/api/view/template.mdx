`template` is the context object available as `$this` inside every PHP view file. It provides the layout system (layout/start/end/slot) and partial inclusion (include). Layout execution runs the child template first to capture slots, then renders the layout.

```txt
Symbol: Skim\View\Template
Source: src/View/Template.php
Lifecycle: instantiated by View::render() per render call, used as $this inside templates
Fallback: defaultLayout applied when template does not call layout()
Test seam: instantiate directly with a views path and data array
```

<CodeExample label="Basic usage" source="llm-generated">
```php
// Inside a template file:
$this->layout('layouts/main');
$this->start('sidebar');
echo '<nav>...</nav>';
$this->end();
<h1><?= e($title) ?></h1>
```
</CodeExample>

<WarningBox>

end() without matching start() throws LogicException

</WarningBox>

<WarningBox>

extract() with EXTR_SKIP means data keys cannot override existing local variables

</WarningBox>

## Architecture

<LifecycleFlow>

```txt
View::render() -> new Template(path, data, defaultLayout)
-> renderFile($template)
-> resolve .html/.php
-> extract data
-> ob_start + include
-> layout declared? -> capture content slot
-> render layout file
-> return HTML
```

</LifecycleFlow>

The layout system uses a two-pass approach: child template runs first to capture slots, then the layout renders with access to those slots. This avoids the need for output buffering the entire page.

<NoteBox>

The layout receives all captured slots from the child template. The 'content' slot is auto-populated with any non-slot output from the child.

</NoteBox>

<ApiMethod name="start">

<ApiSignature>

```php

```

</ApiSignature>

Starts capturing output into a named slot. Must be paired with end().

<ApiParam name="$name" type="string" required>

</ApiMethod>

<ApiMethod name="end">

<ApiSignature>

```php

```

</ApiSignature>
