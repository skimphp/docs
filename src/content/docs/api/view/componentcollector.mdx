`ComponentCollector` captures named content blocks inside components via closures and output buffering. Each render gets its own instance

```txt
Symbol: Skim\View\ComponentCollector
Source: src/View/ComponentCollector.php
Lifecycle: instantiated per componentWithParts() call, pushed onto static stack during capture
Fallback: getPart() returns empty string for missing parts
Test seam: instantiate directly and call captureMain/capturePart
```

<CodeExample label="Basic usage" source="llm-generated">
```php
componentWithParts('card', new CardProps(title: 'Profile'), function($c) {
    $c->part('header', fn() => '<h2>Profile</h2>');
    echo '<p>Main content</p>';
});
```
</CodeExample>

<WarningBox>

Calling current() when stack is empty returns null — global helpers must handle this

</WarningBox>

## Architecture

<LifecycleFlow>

```txt
new ComponentCollector()
-> push onto stack
-> captureMain($render)
-> capturePart($name, $render)
-> pop from stack
-> component template reads getMain/getPart/hasPart
```

</LifecycleFlow>

The static stack replaces a scalar global, enabling nested components. Each collector is independent

<NoteBox>

The static stack is the only shared state

</NoteBox>

## Capture API

<ApiMethod name="captureMain">


</ApiSignature>

</ApiMethod>

## 

<ApiMethod name="resetRequest">

<ApiSignature>

```php
public static function resetRequest(): void
```

</ApiSignature>

Clears the static collector stack between requests in worker mode. #AI:resetRequest

Under normal flow captureMain() pushes then pops, so the stack is empty
between renders. If a component closure throws, the matching pop() never
runs and a stale collector lingers in the process — this drops it so the
next request starts with an empty stack.

</ApiMethod>
