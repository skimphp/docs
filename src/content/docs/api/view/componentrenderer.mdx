`ComponentRenderer` renders reusable UI components in an isolated scope. It supports both legacy array props and readonly *_props objects, validating the latter to enforce naming conventions.

```txt
Symbol: Skim\View\ComponentRenderer
Source: src/View/ComponentRenderer.php
Lifecycle: stateless static class, invoked per component render
Fallback: n/a — stateless
Test seam: use View::setPath() to redirect to test fixtures
```

<CodeExample label="Basic usage" source="llm-generated">
```php
ComponentRenderer::render('alert', ['message' => 'Saved']);
ComponentRenderer::render('alert', new AlertProps(message: 'Saved'));
```
</CodeExample>

<WarningBox>

get_object_vars() only sees public properties — declare DTO props as public readonly

</WarningBox>

## Architecture

<LifecycleFlow>

```txt
render($name, $props)
-> is_object($props)? validatePropsClass()
-> $data = is_object? get_object_vars() : $props
-> new Template(componentsPath(), $data, null)
-> renderFile($name)
-> Profiler::view()
-> return HTML
```

</LifecycleFlow>

Components are intentionally isolated from the layout and shared data systems. This prevents accidental variable leakage and makes components predictable and testable.

<NoteBox>

Components are rendered with a fresh template instance and null layout, guaranteeing no parent template leakage.

</NoteBox>
