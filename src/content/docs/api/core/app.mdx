`Skim\Core\App` is the central application kernel. It combines three responsibilities in one singleton: a scoped key-value store (sys/app/user), a dependency injection container with factory bindings and reflection auto-wiring, and an HTTP kernel with a middleware pipeline. Extensions register services and middleware through `withExtensionContext()` during the boot phase.

```txt
Symbol: Skim\Core\App
Source: src/Core/App.php
Lifecycle: singleton, created on first `instance()` call, booted lazily via `ensureBooted()` in `run()` or `dispatch()`, frozen before request dispatch
Fallback: none — app is the root
Test seam: testInstance() for isolated containers without env/config loading
```

<CodeExample label="Basic usage" source="llm-generated">
```php
$app = App::instance();
$app->router->get('/', [HomeController::class, 'index']);
$app->run();
```
</CodeExample>

<WarningBox>

`run()` installs a global exception handler and is not re-entrant

</WarningBox>

<WarningBox>

`freeze()` is irreversible for the instance lifetime

</WarningBox>

<WarningBox>

sys.* writes throw LogicException in production after first set

</WarningBox>

## Architecture

<LifecycleFlow>

```txt
App::instance()
-> run()
-> ensureBooted()
-> boot() [view layout + router + pipeline + extensionManager::discover + register]
-> profiler/RequestTrace enable (if debug)
-> bootExtensions()
-> freeze()
-> Request::fromGlobals()
-> dispatch()
-> Pipeline::run()
-> callHandler()
-> Response::send()
```

</LifecycleFlow>

The app class is intentionally a god object combining container, kernel, and store. This keeps the framework surface area small — one class to learn, one singleton to pass around. Extensions interact with app exclusively through `withExtensionContext()` during boot, then the app freezes to prevent further mutation.

<NoteBox>

The constructor is private — always use `instance()` or `testInstance()`. Cloning resets resolved singletons and user scope but preserves bindings and sys/app data.

</NoteBox>

## Scoped Store

<ApiMethod name="set">

<ApiSignature>


</ApiSignature>

Stores a value in the scope determined by the key prefix. Keys prefixed `sys.` go to the immutable-after-boot sys scope, `app.` to config scope, `user.` or bare keys to per-request scope. In production (non-debug), sys.* keys throw LogicException on duplicate writes.

<ApiParam name="$key" type="string" required>

Scoped key. Prefix determines target scope: sys.*, app.*, user.*, or bare (→ user).

</ApiParam>

<ApiParam name="$value" type="mixed" required>

Value to store.

</ApiParam>

<ApiThrows type="\LogicException">

When overwriting a sys.* key in production (app.debug === false).

</ApiThrows>

</ApiMethod>

<ApiParam name="$key" type="string" required>

Scoped key to read. Prefix determines source scope.

</ApiParam>

<ApiParam name="$default" type="mixed">
