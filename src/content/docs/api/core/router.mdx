`Skim\Core\Router` wraps nikic/fast-route to compile all routes into a single regex on first dispatch. It supports F3-compatible @param token syntax (@id, @id:int, @slug:str, @any), route groups with additive prefix and middleware, named routes for reverse URL generation, and CLI command routing.

```txt
Symbol: Skim\Core\Router
Source: src/Core/Router.php
Lifecycle: created during app boot, routes registered before freeze(), compiled on first dispatch
Test seam: App::testInstance() creates a fresh router
```

<CodeExample label="Basic usage" source="llm-generated">
```php
$router->get('/users/@id:int', [UserController::class, 'show'])
       ->name('user.show')
       ->middleware(AuthMiddleware::class);
$router->map(['GET', 'HEAD'], '/ping', [health_controller::class, 'ping']);
$router->group('/api/v1', function(Router $r) {
    $r->get('/posts', [PostController::class, 'index']);
}, middleware: [AuthMiddleware::class]);
```
</CodeExample>

<WarningBox>

Route registration after freeze() throws LogicException

</WarningBox>

<WarningBox>

url() requires the app singleton to be available

</WarningBox>

## Architecture

The router is intentionally a thin registration layer over fast-route. All @param token conversion happens at registration time. The compiled dispatcher is cached and invalidated on any route mutation. Groups use a stack to support arbitrary nesting depth.

<NoteBox>

Why fast-route over F3's router: compiles all routes into one regex, orders of magnitude faster than per-route string matching.

</NoteBox>
