`DbException` extends `\RuntimeException` and prepends the failed SQL to the error message. All PDO calls in `Db::` are wrapped so that failures carry the originating query for log and debug output.

```txt
Symbol: Skim\Db\Exceptions\DbException
Source: src/Db/Exceptions/DbException.php
Lifecycle: thrown on PDO failure, caught by application code
Fallback: none
Test seam: trigger with invalid SQL against test_db() SQLite connection
```

<CodeExample label="Basic usage" source="llm-generated">
```php
try {
    Db::query('SELECT * FROM missing_table');
} catch (DbException $e) {
    Log::error($e->getMessage());
}
```
</CodeExample>

## Architecture

<LifecycleFlow>

```txt
PDO operation fails
-> Db:: catches PDOException
-> new DbException(sql, previous)
-> thrown to caller
```

</LifecycleFlow>

Thin wrapper — all intelligence lives in Db::query() and friends.

<NoteBox>

Catch `DbException` specifically — never catch generic `\Exception`.

</NoteBox>
