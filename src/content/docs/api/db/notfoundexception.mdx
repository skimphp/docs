`NotFoundException` is thrown by `Model::findOrFail()` when no record matches the given primary key. Controllers catch it to return structured 404 responses.

```txt

Lifecycle: thrown by findOrFail(), caught by controller or global error handler
Fallback: none
Test seam: expect(fn() => Model::findOrFail(999))->toThrow(NotFoundException::class)
```

$user = User::findOrFail($id); // throws not_found_exception if missing
// In error handler: catch → $res->status(404)->json(['error' => $e->getMessage()])

## Architecture

<LifecycleFlow>

```txt
Model::findOrFail($id)
-> find($id) returns null
-> throw new NotFoundException(static::class, $id)
```

</LifecycleFlow>

Keeps the ORM layer HTTP-agnostic — the exception carries model context, the controller decides the HTTP response.

<NoteBox>

Prefer `find()` returning null when absence is expected. Use `findOrFail()` only when missing is exceptional.

</NoteBox>
